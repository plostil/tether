Pair two devices. See one screen on the other.

Tether links a phone and a PC over an end-to-end encrypted channel and streams the screen peer-to-peer. The server relays sealed blobs. It never holds a key that can decrypt a session.

Run it in one command View the source

How it works

The handshake is the product, and it is visible.
  1. Exchange fingerprints Scan a QR code or type a six-character code. Each device now knows the other's public key.
  2. Prove the keys A Noise_IK handshake runs inside the server's opaque relay. Each side proves it holds the private key behind the fingerprint the other scanned.
  3. Negotiate the session WebRTC signalling travels inside the encrypted channel, so the media path is bound to the paired identity. Impossible requests are refused with a reason.
  4. Stream peer-to-peer Screen video goes device to device over DTLS-SRTP, host to host on a LAN. Both sides show the same session fingerprint. Comparing it is the trust anchor.

What it does

Four modes, gated by what each device can actually do.
  • View a device's screenWatch another device's screen live in the browser.
  • Share this screenShow this screen to a paired device. Needs a Chromium browser opened via localhost.
  • Control an iPhoneDrive an iPhone from the PC over USB through a developer-signed WebDriverAgent bridge.
  • Send text and clipboardEncrypted messages in both directions.

Zero-trust rendezvous

What the server can and cannot see.

The broker authenticates a device by checking that its public key hashes to its device id, routes sealed relay blobs by id, and reports presence. It never parses a payload and never sees session descriptions, ICE candidates, or media.

handshake
Noise_IK_25519_ChaChaPoly_BLAKE2s
media transport
WebRTC, DTLS-SRTP, peer-to-peer
server sees
device ids, presence, sealed blobs
server never sees
keys, SDP, ICE, video
primitives
node:crypto on the server, audited @noble/* in the browser

One handshake implementation runs in Node and in the browser, pinned to shared byte-level test vectors.

Get started

Node 22.18 or newer. Nothing else.
git clone https://github.com/plostil/tether.git
cd tether
npm install
npm run dev

That bundles the web client, starts the broker, and opens http://localhost:8080. Click Try the demo to pair with an in-page virtual device, or Pair a device to link a real phone on your network.

Real two-device pairing, TURN for cross-network sessions, and the iPhone bridge are covered in the deployment and iPhone control guides.

Stated plainly

What it does not do yet.
  • Cross-network sessionsNeed a TURN server. Without one, pairing works on a LAN only.
  • Sharing from a phoneiPhone Safari has no screen-capture API. A phone can view, not share.
  • Controlling a browser pageOS input injection needs a native client. The UI says so rather than pretending.
  • iPhone controlAttended, USB only, with a runner that a free Apple ID re-signs weekly.
  • Native Android and Windows clientsScaffolds today. The web client is the runnable path.
